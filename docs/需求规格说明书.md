# 灵修AI · 需求规格说明书

> 本文档把口述想法整理为可实现的需求。每条需求标注编号，便于后续追溯。

## 一、产品定位

一个**邀请制、无公开注册**的圣经读经灵修 SaaS 工具，面向中国新教基督徒小群体（教会小组、门训小组）。

核心信念：**读经不是信息摄入，而是与神相遇。** 因此产品刻意做成"有约束的、引导式的"，而不是一个随问随答的经文百科。

### 与市面工具的根本差异

| 常见读经 App | 灵修AI |
|---|---|
| 打开就给注释、解经 | **先思考才解锁**，未达标不给答案 |
| 给标准答案 | 给**因人而异的引导**，基于你自己的提问与笔记 |
| "读完" = 划完进度条 | "读完" = 有观察、有提问、有回应、有祷告 |
| AI 当老师 | AI 当**苏格拉底式教练**，只提问不下结论 |

## 二、角色与权限

| 角色 | 权限 |
|---|---|
| 访客 | 只能看登录页与"申请使用"页。**未登录看不到任何功能界面**（R-A1） |
| 成员 | 读经、灵修、笔记、图谱、个人统计 |
| 管理员 | 成员全部权限 + 审批申请、分配/重置密码、维护讲道资源、查看全组进度 |

### R-A 认证需求

- **R-A1** 全站鉴权：除 `/login`、`/apply` 外，所有页面与 API 未登录一律拒绝（中间件层拦截，不依赖前端隐藏）。
- **R-A2** 无自助注册。用户提交手机号 + 姓名 + 备注（如所属教会/小组）形成"使用申请"。
- **R-A3** 管理员在后台审批。通过时**由系统生成初始密码，管理员线下告知用户**（微信/电话），不发短信、不发邮件。
- **R-A4** 用户首次登录强制修改密码。
- **R-A5** 会话用 httpOnly + SameSite Cookie 承载 JWT，默认 30 天。
- **R-A6** 密码用 scrypt 加盐哈希存储，不可逆。
- **R-A7** 登录失败限流，防暴力破解。

## 三、核心功能需求

### R-B 读经（解决"读完就忘"）

- **R-B1** 按经卷/章节阅读，支持自定义每日读经量（默认 4 章）。
- **R-B2** **中英对照**：中文（新标点和合本）与英文（KJV）逐节并列/切换，便于比对语义差异。
- **R-B3** **逐节长按交互**：长按任一节 → 弹出操作面板，可
  - 录音笔记（浏览器 MediaRecorder，存音频 + AI 转写文字）
  - 手写笔记（Canvas 手写，存 PNG）
  - 文字笔记
  - 标记"这节神对我说话"
- **R-B4** **上下文透视**：对选中节，展示其**前 10 节与后 10 节**，并由 AI 说明前文如何铺垫、后文如何回应此节（即上下文对本节的影响）。
- **R-B5** 阅读进度与连续天数（streak）统计。

### R-C 结构化理解（基本要素 + 要义）

- **R-C1** 对读经范围自动抽取结构化要素：**人物、时间、地点、情节脉络、高潮转折、时代背景**。
- **R-C2** **同期事件参考**：该事件发生时，圣经内其他线索与世俗历史上同时期发生了什么。
- **R-C3** **知识图谱出图**：把人物/地点/事件及其关系渲染为图谱，可导出 PNG。
- **R-C4** **思维导图出图**：把整段经文脉络渲染为思维导图，可导出 PNG。
- **R-C5** 抽取结果缓存，同一段落不重复消耗 AI 额度。

### R-D 约束式灵修流程（本产品的灵魂）

流程为**七个阶段，强制顺序推进，不可跳跃**：

| 阶段 | 名称 | 用户要做的 | 系统约束 |
|---|---|---|---|
| 1 | 观察 | 写下自己看到的事实（人物/时间/地点/情节） | 至少 N 字，否则不能进入下一步 |
| 2 | 自提问 | **自己提出问题**（不是回答系统的问题） | 至少 2 个问题，且 AI 评估其"提问质量" |
| 3 | 默想作答 | 回答系统与自己的问题 | AI 打分，**未达阈值不解锁提示** |
| 4 | 引导揭晓 | 与 AI 教练对话 | AI **不给标准答案**，按 R-D3 规则引导 |
| 5 | 生命实事 | 记录自己生命中真实发生的事、看到的现象 | 结构化记录，可回溯 |
| 6 | 祷告 | 写下/录下回应神的祷告 | 完成后本次灵修才算完整 |
| 7 | 完成 | 生成本次灵修卡片 | 归档，可回看 |

- **R-D1** **不先给答案**：界面在用户提交自己的思考之前，不显示任何解经内容、AI 提示、参考答案。
- **R-D2** **评分解锁**：AI 对用户的观察/提问/作答按维度打分（观察准确度、提问深度、经文要义把握、个人化程度），总分达阈值（默认 60）才解锁下一层提示。
- **R-D3** **引导式揭晓**（关键约束，写入 System Prompt）：
  - 不给标准答案，先**回应他自己的提问与笔记**，指出他已经看见了什么。
  - 用**追问**推进，而非陈述结论。
  - 因人而异：参考该用户历史笔记与本次输入，做个性化引导。
  - 知识性、基础性内容（历史背景、原文词义、地理、度量单位）**可以直接补充**，这不算"给答案"。
- **R-D4** **提问要触及整段要义**，而不只是"谁在哪里做了什么"的事实题。系统生成的问题必须覆盖：事实层 / 脉络层 / 神学要义层 / 处境应用层。
- **R-D5** **自动追问兜底**：若用户读完却没有任何感悟输入，智能体主动发问，引发思考，否则不判定为"已读"。
- **R-D6** **"读过"的判定**：必须满足 有观察 + 有提问/作答 + 有回应或祷告，纯翻页不算读过。

### R-E 思辨式提问（用熟悉的文化载体作桥）

- **R-E1** AI 出题时优先引用用户熟悉的文化载体：**诗歌/流行歌曲、电影、名著、社会热点**，让用户做判断与思辨。
- **R-E2** 题目必须是**主观思辨题**，禁止出单选题式"考试题"，禁止有唯一正确答案的问法。
- **R-E3** 若配置了知识库（教会讲道稿、推荐书目），优先从知识库取材；否则退回到大众熟知的文化素材。
- **R-E4** 联系**当下社会现象与互联网热点**，引发对经文的现实反思。

### R-F 资源（讲道视频等）

- **R-F1** 管理员可为经文范围挂载外部资源：福音影视网、讲道集、YouTube/B站 链接，含标题、讲员、时间区间、备注。
- **R-F2** 阅读某段经文时，自动匹配并展示覆盖该范围的资源，点击跳转外部播放。
- **R-F3** 支持记录视频**起止时间点**，实现"截取该节相关讲道片段"的效果（跳转带时间参数）。

### R-G 移动端

- **R-G1** 移动优先，**底部 Tab 导航**（5 个：今日 / 读经 / 灵修 / 发现 / 我的）。
- **R-G2** 适配 iOS 安全区（`env(safe-area-inset-bottom)`），避免底部横条遮挡。
- **R-G3** 可嵌入微信小程序 `web-view`：不依赖微信 JS-SDK、不依赖 `window.open`、Cookie 走同站、页面内不弹系统对话框。
- **R-G4** 长按交互需兼容触屏（touch 事件 + 阻止默认文本选择与系统菜单）。
- **R-G5** 纯网站形式交付，不做小程序原生包。

## 四、数据模型

```
users              成员（含 role/status，首登改密标记）
access_requests    使用申请（待审批 → 通过/拒绝）
login_attempts     登录限流
bible_books        66 卷书元数据（中英名、章数、分类）
bible_verses       经文（book_id, chapter, verse, cn, en）
reading_settings   每人的每日章数、当前进度
reading_logs       每日阅读记录（含是否达成"读过"判定）
devotions          一次灵修会话（范围、阶段、总分、状态）
devotion_inputs    用户输入（观察/提问/作答/实事/祷告，按 kind 区分）
devotion_scores    AI 评分明细（维度 + 分数 + 理由）
coach_messages     引导式对话历史
verse_notes        逐节笔记（text/audio/handwriting + 是否"神对我说话"）
passage_insights   结构化抽取缓存（要素/同期事件/图谱/思维导图/上下文分析）
sermon_resources   讲道视频等外部资源（按经文范围匹配）
knowledge_docs     可选知识库（讲道稿、书摘）
```

## 五、非功能需求

- **R-N1** 单机可部署：SQLite 落盘，无需外部数据库。
- **R-N2** AI 供应商可换：走 OpenAI 兼容协议，模型名与 BaseURL 走环境变量。
- **R-N3** AI 不可用时降级：内置规则引擎生成基础问题与评分，功能不中断。
- **R-N4** AI 调用结果尽量缓存，控制成本。
- **R-N5** 版权：中文用**新标点和合本**、英文用 **KJV（公有领域）**。仅限受邀小群体内部学习使用；数据源与版本可由管理员替换。

## 六、明确不做

- 不做微信小程序原生包、不做微信登录
- 不做公开注册、不做短信/邮件发送
- 不做支付订阅
- AI 不代替用户灵修、不下神学定论、不做教义裁判
